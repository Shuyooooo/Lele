# 🧠 Memory Rewrite - 核心机制文档

## 一句话目标

**玩家在「过去」写入信息 → 在「现在」凭记忆验证 → 世界改变**

---

## 核心机制

### Mechanic: 记忆验证链路

**Purpose**  
让玩家体验"过去的选择决定现在的可能"，通过记忆行为将因果关系具象化。

**Player Fantasy**  
感受到自己的决定真的改变了世界，而不是看一个演示。

**Input**  
1. 玩家在 Past 场景输入一段信息（例：4 位数字）
2. 玩家回到 Present 场景，手动输入同一信息
3. 输入检验完成

**Output**  
- 验证通过 → 场景改变（灯光/UI 状态/文本提示）
- 验证失败 → 提示"记忆不符"，允许重试

**Success Condition**  
玩家完成一次完整链路：Past 写入 → Present 验证 → 世界改变

**Failure State**  
玩家输错 → 明确反馈 → 允许重试（无额外成本）

**Tuning Levers**  
- 信息难度：4 位数字 ↔ 6 位数字（易调）
- 重试次数：无限 ↔ 有限制（测试易忘性）
- 反馈延迟：即时 ↔ 短延迟（测试期待感）

---

## 核心循环

| 阶段 | 时长 | 玩家操作 | 反馈 |
|------|------|--------|------|
| **Past** | 5-10s | 看场景、输入信息 | 明确的输入确认 |
| **回到 Present** | 1-2s | 场景切换 | 灯光/UI 变化体现时间流逝 |
| **Present 验证** | 10-15s | 手动输入相同信息 | 成功=世界改变；失败=重试提示 |

**整个循环**：30s 以内，玩家能清楚感受"因果"

---

## 场景结构（超简）

### Scene: DeskNow（过去 - 输入信息）

**核心要素**：
- 电脑/笔记本（一个交互热点）
- 一个"思考圆"UI（输入框）
- 灯光略暗（表示"过去"）

**交互**：
- 玩家点击电脑 → 弹出思考圆 UI
- 输入 4 位信息（允许任意组合）
- 提交 → 自动回到 Present

**不要加**：
- 复杂的场景布局
- 多个交互热点
- 对话或剧情说明

---

### Scene: DeskNow（现在 - 验证信息）

**核心要素**：
- 电脑/笔记本（锁定状态显示）
- 一个"输入框"（进行验证）
- 灯光更亮/色温回暖（表示"现在"）

**交互**：
- 玩家点击电脑 → 显示输入界面
- 玩家手动输入 4 位
- 检验：
  - ✓ 正确 → 电脑解锁 + 灯光变化 + 提示"记录已同步"
  - ✗ 错误 → 提示"不符" + 允许重试

**不要加**：
- 密码提示
- 多套规则
- 额外的验证步骤

---

## 状态机制（极简）

```javascript
{
  memory: {
    pastCode: null,      // Past 输入的 4 位信息
    isUnlocked: false,   // 是否已解锁
    scene: 'present'     // 'present' 或 'past'
  }
}
```

**流程**：
1. `scene === 'past'` → 玩家输入 → `pastCode` 写入
2. 切换到 `scene === 'present'`
3. 玩家输入验证 → 对比 `pastCode`
4. 匹配成功 → `isUnlocked = true` → 触发 UI 变化

---

## 世界改变反馈（成功后）

选 **2 项** 组合：

1. **电脑 UI**：从"锁定状态" → "欢迎界面"
2. **灯光**：从冷色 → 暖色（配合"时间推移"的设定）
3. **文本提示**：短消息"记录已同步"（1-2s 后消失）
4. **轻微效果**：屏幕闪烁或渐变（可选）

**关键**：不需要复杂动画，改变即可。

## 关卡流程（可扩展模板）

### Chapter 1: Desk（最小 MVP）

- **Past**：玩家输入 4 位数字
- **Present**：玩家验证 → 解锁 → 灯光亮起
- **目标**：完成一次"过去决定现在"的体验

### Chapter 2: Bedroom（未来迭代）

- **Past**：玩家修改房间内的一个细节（例：窗帘开/闭）
- **Present**：房间状态变化反映该修改
- **扩展**：增加"空间因果"维度

### Chapter 3: System（未来迭代）

- **多个记忆点**：玩家需要在多个 Past 时刻写入信息
- **Present 验证**：一个总验证，检查所有记忆点
- **扩展**：增加"系统复杂度"维度

---

## 成功验收（Demo 版）

玩家能否：
- ✓ 完成一次 Past → Present 的链路
- ✓ 说出或表现出理解："我写过 1234，所以现在能解锁"
- ✓ 愿意再试一次（验证记忆）

如果满足 3 项 → Demo 成功

## 开发优先级

| 优先级 | 任务 | 预计时间 |
|--------|------|--------|
| **P1** | Present：电脑 UI + 输入框 + 成功/失败反馈 | 2h |
| **P1** | Past：思考圆 UI + 输入提交 | 1h |
| **P1** | 状态存储 + 场景切换逻辑 | 1h |
| **P2** | 灯光切换 + 世界改变反馈 | 1h |
| **P3** | 美化 UI 样式（可以后做） | 1h |

**MVP 目标**：P1 全部完成 = 可玩 demo

---

## 不在范围内（Demo 纯度）

- ❌ 多个房间/复杂导航
- ❌ 对话系统或剧情分支
- ❌ 多种类型的信息（只用数字）
- ❌ 高保真美术资源
- ❌ 音乐/音效（可后加）
